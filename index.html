How I work

Most of my work sits between a language model and a database that a business already trusts. That gap is where things quietly break: a query that looks right but reads the wrong column, a retrieval step that cites a document the reader cannot open, an agent that answers confidently instead of asking.

So I spend the effort on the unglamorous parts. Schema retrieval before generation, validation before the result reaches a screen, evaluation before a prompt ships, and a clear path for a human to take over. The interesting demo is the easy half.

I work in Python, mostly with Azure OpenAI, LangChain and LangGraph on the Microsoft side, and Google's ADK and Cloud Run on the GCP side. Before that I was writing Django REST APIs and cleaning student datasets, which is where I learned that data quality decides more outcomes than model choice.
